# Memoria del Proyecto Afrolash

Este documento almacena el estado persistente, decisiones técnicas y el historial de progreso de **Afrolash**.

---

## 1. Estado Actual del Sistema

- **Versión / Stack**: Frontend React 19 (`client/` v0.1.0) + Backend Node.js / Express 5 (`server/` v1.0.0) + MySQL 8 (`mysql2/promise`). Dependencias auditadas y remediadas bajo la Spec 001 (0 vulnerabilidades críticas y 0 altas tanto en `server/` como en `client/`; 0 vulnerabilidades en runtime de producción en backend).
- **Estado de Compilación y Pruebas**: Proyecto estructurado en `client/` y `server/`.
  - **Frontend SPA**: Compilación de producción Create React App (`npm --prefix client run build`) con código de salida 0 y cero advertencias críticas de ESLint. Cuenta con 6 suites de pruebas Jest/React Testing Library (`client/src/App.test.js`, `client/src/Carrito.test.js`, `client/src/TiendaVistas.test.js`, `client/src/CuentaLegalVistas.test.js`, `client/src/AdminVistas.test.js`, `client/src/config/api.test.js`) sumando 47 pruebas en verde al 100% que validan el marco global, accesibilidad por teclado/Escape, carrusel, stepper de checkout de 4 etapas, autenticación, perfil, historial de pedidos, documentos legales, permisos administrativos y resolución determinista de URLs/imágenes.
  - **Backend API**: Configuración de Jest + Supertest (`npm --prefix server test`) con 3 suites integrales en verde (`server/auditoria.test.js`, `server/seguridad.test.js`, `server/produccion.test.js` sumando 41 pruebas al 100%) validando disparadores de auditoría, cabeceras Helmet, CORS dual (permisivo en `/api/health` y `/img`, y restrictivo en rutas transaccionales de negocio), limitador de tasa contra fuerza bruta, control de payloads JSON/archivos con limpieza en disco, transacciones atómicas con bloqueo pesimista `SELECT ... FOR UPDATE`, recálculo autoritativo de precios (*anti-price tampering*), inmunidad IDOR, validaciones de contraseñas, escape HTML en correos salientes sobre puertos efímeros, helpers de configuración en la nube (`parsearTrustProxy`, `construirOpcionesSSL`) e idempotencia estricta de `database/schema.sql` y `database/seed.sql`.
- **Persistencia / Datos**: Base de datos relacional MySQL (`afrolash_db`) gestionada por pool de conexiones asíncrono (`server/config/db.js`) con soporte TLS/SSL condicional (`DB_SSL`) para MySQL en la nube (Aiven, TiDB). Estructurada con 5 tablas físicas estandarizadas en minúsculas en orden foráneo estricto (`usuarios`, `productos`, `pedidos`, `detalles_pedido`, `auditoria`), garantizando compatibilidad con servidores Linux (`lower_case_table_names=0`). Provista de scripts reproducibles e idempotentes `database/schema.sql` (con integridad referencial `ON DELETE CASCADE`/`RESTRICT` y 6 triggers de auditoría con delimitadores estándar) y `database/seed.sql` (catálogo cosmético completo con imágenes y cuentas de demostración seguras con hashes `bcryptjs`).
- **Servicios / Interfaces**:
  - **API REST (`server/`, puerto 5000)**:
    - `/api/health`: endpoint público de diagnóstico con CORS permisivo propio, verificación `SELECT 1` y respuestas HTTP 200/503 JSON sin exponer trazas de error.
    - `/img`: servido estático público de recursos de catálogo bajo `express.static` con cabecera `Cross-Origin-Resource-Policy: cross-origin`.
    - `/api/auth`: registro, login JWT, perfil, recuperación/restablecimiento de contraseña por correo.
    - `/api/usuarios`: listado de usuarios, alta de empleados con contraseña temporal enviada por correo y eliminación restringida a rol `empleado` (exclusivo de `admin`).
    - `/api/productos`: catálogo público, detalle individual con ingredientes/instrucciones/consejos/precauciones, lectura de inventario para `admin` y `empleado` (`verificarPersonal`), y CRUD/visibilidad exclusivo de `admin`.
    - `/api/pedidos`: procesamiento atómico de orden, descuento pesimista de stock, generación de factura PDF con `pdfkit` + envío por `nodemailer`, historial de cliente y gestión operativa de ventas para `admin` y `empleado` (`verificarPersonal`).
    - `/api/pagos`: PaymentIntents de Stripe en USD.
  - **SPA Frontend (`client/`, puerto 3000)**: Sistema de diseño editorial cosmético "Rose Noir & Gold" con tipografía dual (`Cormorant Garamond` y `Plus Jakarta Sans`), navegación accesible por teclado y tecla `Escape`, modales/toasts accesibles (`role="dialog"`, `role="alertdialog"`), stepper visual de checkout de 4 etapas, vistas operativas modulares responsivas (`AdminInventario`, `AdminVentas`, `AdminMetricas` con Recharts, `AdminUsuarios`), `DocumentosLegales` navegables y botón flotante de WhatsApp. Desacoplado mediante `client/src/config/api.js` (con respaldo automático en `http://localhost:5000`) y provisto de reglas de enrutamiento SPA para Vercel (`client/vercel.json`) y Netlify (`client/public/_redirects`).
  - **Documentación y Portafolio**: `README.md` orientado a presentación de portafolio profesional y `docs/deployment.md` con la guía paso a paso 100% gratuita para desplegar la arquitectura completa en la nube (Aiven/TiDB + Render + Vercel/Netlify).

## 4. Deuda Técnica y Pendientes Inmediatos

1. **Excepciones residuales de dependencias (RF-05, Spec 001)**:
   - `deepmerge >=4.2.0` (baja): presente en sub-dependencias de desarrollo/build tools (`jest-config` en `server/`; `workbox-build`, `@svgr/webpack`, `fork-ts-checker-webpack-plugin`, `jest-config` en `client/`). No cuenta con versión parcheada en la rama 4.x y forzar una actualización mayor degradaría o rompería las herramientas de compilación/pruebas.
   - `webpack-dev-server <=5.2.5` (moderada): anclado estrictamente por `react-scripts@5.0.1` en desarrollo. Un override a v5 rompe la API de configuración interna de Create React App v5 (`onBeforeSetupMiddleware` / `onAfterSetupMiddleware`), por lo que se mantiene confinado a entorno de desarrollo local sin impacto en el artefacto de producción generado por `npm run build`.
2. **Cobertura de pruebas automatizadas en backend**: Consolidar y extender pruebas unitarias de controladores administrativos secundarios aprovechando la infraestructura de puertos efímeros y mocks establecida en `server/seguridad.test.js`.
3. **Limpieza opcional de paquete residual (`bcrypt`)**: El código de `server/` ya está unificado en `bcryptjs` (Spec 003 y Spec 004); únicamente queda desinstalar opcionalmente la dependencia nativa no referenciada `bcrypt` en `server/package.json`.
