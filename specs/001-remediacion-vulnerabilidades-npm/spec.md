# Especificación: 001 - Remediación de Vulnerabilidades de Dependencias NPM en Server y Client

**Estado:** Aprobado
**Fecha:** 2026-11-14

## 1. Propósito y Contexto
- **Qué**: Remediación sistemática de vulnerabilidades de seguridad en las dependencias directas y transitivas de `server/` (actualmente 22 vulnerabilidades: 1 crítica, 7 altas, 11 moderadas, 3 bajas) y `client/` (actualmente 68 vulnerabilidades: 3 críticas, 34 altas, 14 moderadas, 17 bajas) mediante actualizaciones compatibles, `npm audit fix` no destructivo y directivas `overrides` en `package.json`.
- **Por qué**: Proteger el backend Express/MySQL y el frontend React contra vectores de denegación de servicio (DoS/ReDoS), contaminación de prototipos (*prototype pollution*), falsificación de IP (`proxy-addr`), inyección de cabeceras/CRLF (`axios`, `form-data`), desvío de destinatarios SMTP (`nodemailer`), fugas de credenciales (`mysql2`), lectura/escritura arbitraria de archivos y ejecución remota de código en herramientas de build, preservando al 100% la estabilidad funcional y el catálogo actual de dependencias.

## 2. Requisitos Funcionales (EARS)
- **RF-01 (Remediación de vulnerabilidades críticas y altas de runtime en Backend)**: El sistema DEBERÁ actualizar las dependencias directas y transitivas de producción en `server/` (`mysql2`, `multer`, `nodemailer`, `body-parser`, `proxy-addr`, `qs`, `brace-expansion`, `js-yaml`) a versiones parcheadas de modo que `npm --prefix server audit --omit=dev` reporte **0 vulnerabilidades críticas y 0 vulnerabilidades altas**.
- **RF-02 (Remediación de vulnerabilidades de desarrollo y transitivas en Backend)**: CUANDO existan vulnerabilidades en sub-dependencias de herramientas de desarrollo de `server/` (`jest`, `nodemon`, tales como `glob`, `minimatch`, `deepmerge`, `browserslist`, `baseline-browser-mapping`) que no se resuelvan con `npm audit fix` estándar, el sistema DEBERÁ aplicar resoluciones mediante el campo `overrides` en `server/package.json` para reducir al mínimo las vulnerabilidades totales sin degradar `jest` ni `nodemon` a versiones incompatibles.
- **RF-03 (Remediación de vulnerabilidades críticas y altas en Frontend)**: El sistema DEBERÁ actualizar las dependencias directas y transitivas vulnerables en `client/` (incluyendo `axios`, `react-router`/`react-router-dom`, `shell-quote`, `websocket-driver`, `proxy-addr`, `ws`, `node-forge`, `lodash`, `underscore`, `flatted`, `fast-uri`, `form-data`, `nanoid`, `picomatch`, `path-to-regexp`, `rollup`, `source-map-js`, `compression`, `body-parser`, `launch-editor`, `@babel/core`, `@babel/plugin-transform-modules-systemjs`) mediante `npm audit fix` y actualizaciones compatibles, de modo que `npm --prefix client audit` reporte **0 vulnerabilidades críticas** y elimine todas las vulnerabilidades altas y moderadas que cuenten con parche compatible vía `npm audit fix` u `overrides` seguros.
- **RF-04 (Aplicación controlada de `overrides` en Frontend sin romper `react-scripts`)**: CUANDO una vulnerabilidad transitiva en `client/` pertenezca a la cadena de `react-scripts@5.0.1` o `exceljs` (tales como `serialize-javascript`, `nth-check`, `postcss`, `webpack-dev-middleware`, `uuid`, `@tootallnate/once`, `deepmerge`) y `npm audit fix --force` proponga degradar `react-scripts` o `exceljs` a versiones incompatibles, el sistema DEBERÁ aplicar `overrides` en `client/package.json` únicamente para aquellas sub-dependencias cuyas versiones parcheadas resuelvan `npm --prefix client install` sin errores de árbol `ERESOLVE`, permitan completar exitosamente `npm --prefix client run build` y superen `npm --prefix client test -- --watchAll=false --testPathPattern=Carrito.test.js` sin introducir errores de importación o resolución de módulos en `App.test.js`.
- **RF-05 (Reversión selectiva y resolución de `ERESOLVE` ante incompatibilidad de `override`)**: SI la aplicación de un `override` específico en `client/package.json` o `server/package.json` provoca errores de resolución del árbol de dependencias (`ERESOLVE unable to resolve dependency tree`), errores de compilación, fallos en pruebas automatizadas o errores de carga de módulos, ENTONCES el sistema DEBERÁ confinar el `override` al paquete padre específico en el árbol o descartar/ajustar únicamente ese `override` conflictivo sin utilizar `--force`, conservando el resto de las remediaciones y documentando la excepción técnica resultante.
- **RF-06 (Preservación del catálogo de dependencias y código fuente)**: MIENTRAS se ejecute el proceso de actualización y remediación de vulnerabilidades, el sistema DEBERÁ mantener todas las dependencias directas actuales declaradas en `server/package.json` y `client/package.json` sin eliminar paquetes ni modificar archivos de código fuente de la aplicación, salvo que una actualización de seguridad estrictamente necesaria requiera un ajuste mínimo de compatibilidad de API.
- **RF-07 (Integridad de `package-lock.json` y verificación de regresión)**: CUANDO concluya la actualización de paquetes en `server/` y `client/`, el sistema DEBERÁ regenerar y sincronizar `server/package-lock.json` y `client/package-lock.json` garantizando que `npm --prefix client run build`, `node --check server/index.js`, la carga programática de los módulos de `server/` (rutas, controladores, middlewares y utilidades), `npm --prefix client test -- --watchAll=false --testPathPattern=Carrito.test.js` y la ausencia de fallos de importación/resolución en `App.test.js` se ejecuten correctamente; y respecto a `npm --prefix server test`, ejecutará `server/auditoria.test.js` en verde cuando la base de datos MySQL (`afrolash_db`) esté disponible, o verificará la ausencia de errores de dependencias/resolución en Jest en caso de indisponibilidad de BD en el entorno.

## 3. Casos Límite y Restricciones
- **Prohibición de `--force` destructivo**: Queda estrictamente prohibido ejecutar `npm audit fix --force` o `npm install --force` de forma ciega, ya que degradan `react-scripts` a `0.0.0`, `jest` a `25.1.0`, `nodemon` a `3.1.11` y `exceljs` a `3.4.0`, o rompen la reproducibilidad del árbol.
- **Conflictos de `peerDependencies` y error `ERESOLVE`**: React 19 con `@testing-library/*` o `react-scripts@5.0.1` puede producir errores `ERESOLVE unable to resolve dependency tree` al aplicar `overrides` globales; en tales casos debe aplicarse el `override` acotado al paquete padre o revertirse conforme a RF-05 hasta que `npm install` y `package-lock.json` queden limpios e idempotentes.
- **Incompatibilidades de API mayor en sub-dependencias**: Paquetes como `uuid` v11 (ESM-only), `postcss`, `svgo`/`nth-check`, `webpack-dev-middleware` o `deepmerge` dentro de `react-scripts@5.0.1`, `exceljs` o `jest` pueden romper el formato CommonJS o los plugins de Webpack 5 / Babel; ante cualquier fallo aplica RF-05 (excluir o fijar la versión máxima compatible).
- **Alcance de las suites de prueba existentes**:
  - En `client/`, `client/src/Carrito.test.js` constituye la prueba funcional activa; `client/src/App.test.js` conserva el test de plantilla de Create React App (`/learn react/i`) que no corresponde a la interfaz actual de Afrolash, por lo que no debe tomarse ese aserto heredado como regresión de dependencias (aunque sí debe comprobarse que la compilación e importación de `App` y sus dependencias no fallen).
  - En `server/`, `server/auditoria.test.js` requiere conexión activa a la base de datos MySQL (`afrolash_db`); si MySQL no está disponible en el entorno de ejecución, la verificación de no-regresión deberá validar igualmente la sintaxis (`node --check`), la carga de módulos (`require` de controladores, rutas, middlewares y utilidades) y la ausencia de errores de resolución de dependencias en Jest.

## 4. Criterios de Aceptación
- [ ] `npm --prefix server audit --omit=dev` reporta **0 vulnerabilidades críticas y 0 altas** en dependencias de producción (y `npm --prefix server audit` reporta **0 críticas y 0 altas** en el total o documenta cualquier excepción justificada por RF-05).
- [ ] `npm --prefix client audit` reporta **0 vulnerabilidades críticas** y elimina todas las vulnerabilidades altas y moderadas con parche compatible vía `npm audit fix` u `overrides` seguros.
- [ ] `npm --prefix server install` y `npm --prefix client install` se completan sin errores `ERESOLVE` y mantienen `package-lock.json` idempotente en reinstalaciones limpias.
- [ ] `npm --prefix client run build` finaliza con código de salida `0` y sin errores ni advertencias críticas de compilación.
- [ ] `node --check server/index.js` y la carga de módulos de `server/` finalizan sin errores.
- [ ] `npm --prefix client test -- --watchAll=false --testPathPattern=Carrito.test.js` pasa en verde, `App.test.js` no arroja errores de importación/resolución de módulos y `npm --prefix server test` pasa en verde (con MySQL disponible) o no falla por dependencias rotas.
- [ ] Cualquier vulnerabilidad transitiva residual que no pueda resolverse sin romper `react-scripts@5.0.1`, `exceljs` o `jest` queda documentada explícitamente con su causa técnica en el reporte de cierre y en `MEMORY.md`.
